# Модель возможностей портфолио

Этот справочник выведен из изученного сайта на Flask/Jinja/SQLite. Это спецификация для новой реализации; исходный код и частные материалы в скилл не включены.

| Возможность исходника | Как использовать в новом сайте |
| --- | --- |
| Главная: первый экран, работы, процесс, цены, автор, FAQ, контакты | Выбрать нужные разделы и новый порядок под задачу владельца |
| Изображения работ и полноразмерный просмотр | Сохранить ясность каталога и управление с клавиатуры; заново разработать раскладку |
| Каналы, результаты, показатели | Включать только собственные подтверждённые данные; иначе скрывать |
| Защищённая админка работ | Добавление, замена изображения, название, alt, порядок, публикация и архив |
| Редактор контента | Тексты секций, услуги, FAQ, сведения об авторе и контакты |
| Предпросмотр публичной версии | Позволить проверить, что действительно увидит посетитель |
| Оптимизированные изображения и оригиналы | Создавать размеры для каталога; оригиналы хранить отдельно от публичных файлов |
| Резервное копирование и отдельное восстановление | Согласованный снимок данных; проверенное восстановление в пустую директорию |
| Форма связи | Валидация и честный результат; подключение конкретного владельца с нуля |
| Пакет исходников и частный релиз для хостинга | Разные типы экспорта: публичный код не содержит рабочую базу и частные материалы |

## Дополнения для переиспользования

Категории работ, поиск, переключение тем, выбор шрифтов и универсальная конфигурация — требования к новому скиллу, а не заявление, что все они уже работали в исходнике.

Для каталога:

- Категории задаются в `site.config.json` как `{"id":"branding","label":"Айдентика"}`. `id` стабилен и не зависит от перевода названия.
- У работы могут быть несколько категорий. Фильтр должен содержать «Все», активное состояние и понятный пустой результат. Поиск добавляется только если он нужен и включён.
- Порядок `manual` использует `position`, затем `id`; `newest` — `year` по убыванию, затем `position` и `id`. При необходимости конкретной даты расширь схему явным полем, а не угадывай её из имени файла.
- Прямой путь к изображению скрытой/архивной работы также должен закрываться, если это приватный черновик. На публичном статическом хостинге не выгружай такие изображения вообще.
- Каталог — это коллекция работ. Корзина, платежи и оформление покупки добавляются только по отдельному запросу.

Схема записи `catalog.json`:

```json
{
  "schema_version": 1,
  "works": [
    {
      "id": "project-01",
      "title": "Название собственной работы",
      "categories": ["branding"],
      "image": "assets/media/project-01.webp",
      "alt": "Конкретное описание изображения",
      "width": 1600,
      "height": 1000,
      "description": "Задача и вклад автора",
      "year": 2026,
      "position": 0,
      "published": true,
      "archived": false,
      "demo": false
    }
  ]
}
```

`image` — относительный путь внутри проекта без `..`. Числа размеров должны совпадать с изображением; пример не задаёт обязательное соотношение сторон. `demo: true` означает демонстрационный материал и требует заметной маркировки в предпросмотре, а не выдачи за клиентский проект.

Тексты в `content.services`: объекты `title`, `description`. `content.process`: `title`, `description`. `content.faq`: `question`, `answer`. `pricing.packages`: `name`, `price` (готовая строка без угадывания валюты), `description`, `features` (список строк), `cta_label`. Результаты в `content.proof`: `title`, `description`, `verified` (булево) и `source` (описание или ссылка на подтверждение); в публичную версию допускаются только `verified: true` с указанным источником.

`contact.links`: объекты `label`, `url`; `theme.fonts.*.files`: относительные пути к локальным файлам. В конфигурации не хранятся ключи, пароли и токены.
