# Реализация и контракт настроек

## Граница пакета

Скилл содержит бриф, примеры данных и инструкции. Он не содержит Flask-приложение и не применяет настройки сам. При использовании создай реальный загрузчик, шаблоны/компоненты, стили, обработчики и руководство в проекте пользователя. Не заявляй готовность сайта после одного заполнения JSON.

## Выбор среды

Сначала прочитай существующий проект и его инструкции. Сохрани согласованный стек. Для нового проекта с собственной админкой функциональная модель исходника подходит для Flask + Jinja + SQLite и обычного CSS/JS. Для статического размещения создай статический сайт с редактированием данных через репозиторий либо явно выбранную CMS. Если человек просит админку и выбрал статический хостинг, объясни выбор совместимого решения до обещания полной готовности.

Версии библиотек и инструкции выбранного хостинга проверяй по актуальным официальным источникам при реализации. Не переноси список зависимостей и старый домен частного сайта. Предоставь понятный локальный запуск и необходимые переменные окружения.

## Пример разделения для Flask

```text
site.config.json             выбранная тема, структура, тексты и контакты
catalog.json                 исходные данные каталога
portfolio/__init__.py        создание приложения, публичные маршруты
portfolio/content.py         загрузка, проверка и сохранение контента
portfolio/catalog.py         категории, фильтры, сортировка, видимость
portfolio/admin.py           защищённое редактирование
portfolio/storage.py         база и миграции
portfolio/uploads.py         обработка изображений
portfolio/contact.py         адаптер выбранного способа связи
portfolio/templates/         собственные шаблоны проекта
portfolio/static/            общие стили/скрипты, разрешённые публичные ресурсы
instance/                   рабочая база и загруженные файлы; вне публичного репозитория
tests/                      проверки реальных пользовательских действий
.env.example                только имена переменных и безопасные пустые значения
```

Это ориентир, а не требование имён. Если используешь базу как основной источник, JSON служит начальным импортом/экспортом. Не перечитывай и не перезаписывай исходным JSON пользовательские изменения при каждом запуске. Если используешь JSON как основной источник, сохраняй его атомарно и не допускай тихой потери параллельных правок. Выбери один авторитетный источник и опиши его в руководстве.

## Применение настроек

| Группа | Ожидаемое поведение |
| --- | --- |
| `identity` | Имя/специализация, язык HTML, домен для canonical/OG; не жёстко в шаблоне |
| `hero` | Новый текст, подпись кнопки и действующий переход |
| `theme.colors` | CSS-переменные фона, карточек, текста, акцента и кнопок |
| `theme.fonts` | Две независимые гарнитуры, запасные шрифты, локальные `@font-face` при наличии файлов |
| `theme.mode` | `light` или `dark`: согласованная выбранная палитра; `system`: две полноценные палитры и предпочтение ОС |
| `theme.direction` | Свободное название принятой концепции; запись сама по себе не меняет внешний вид |
| `theme.radius_px`, `max_width_px`, `density` | Видимая геометрия и отступы, читаемые на телефоне |
| `theme.motion` | `none`, `subtle`, `expressive`; всегда учитывать уменьшение движения |
| `layout` | Реальная композиция, навигация, тип каталога и порядок включённых секций |
| `catalog` | Категории, фильтры, поиск при включении, сортировка, подписи и просмотр |
| `content` | Тексты секций; пустые секции скрываются или честно отмечаются в черновике |
| `pricing` | `hidden`, `on-request`, `from`, `packages`; валюта не подставляется автоматически |
| `contact` | `links` или `form`; сервис и отправка настраиваются отдельно от публичных данных |
| `admin` | Включённое реальное управление; выключенное не должно оставлять открытые маршруты записи |
| `seo` | Title/description и разрешённое собственное изображение для ссылок |

`system` требует дополнительного `theme.dark_colors` с теми же ключами, что `colors` (светлая палитра). Конфигурационный валидатор проверяет обе. При пользовательском переключателе темы сохраняй выбор локально и не вызывай вспышку неверного фона.

Основные имена макетов: hero — `split`, `work-first`, `statement`, `portrait`, `feature`; navigation — `top`, `side`, `compact`; gallery — `grid`, `editorial`, `index`, `stack`. Это контракт стартовой схемы; если задача требует новой композиции, расширь схему, валидатор и реализацию вместе. Не надо реализовывать все варианты для одного сайта: реализуй выбранные и поддержи заявленные пользователю переключения.

Шрифтовые имена и пути из настроек нужно валидировать и безопасно сериализовать в CSS; не вставляй произвольную строку как необработанный CSS/HTML. Тексты экранируй, ссылки ограничивай безопасными схемами. Наличие правильных полей в JSON не доказывает, что сайт применяет их.

## Админка и материалы

Для админки: индивидуальная настройка доступа, хэш пароля, защищённые сессии, CSRF для действий записи, ограничение попыток входа, проверка изображения по содержимому, лимиты загрузки. Не задавай общий пароль в публичном репозитории. Загруженные файлы именуй безопасно, приватные оригиналы и черновики выдавай через проверку доступа. В существующем проекте изменения схемы выполняй миграциями с сохранением данных.

Верификацию доказательств отделяй от визуального оформления. Пользователь с доступом редактирует запись, а публичный сайт фильтрует её по `verified` и наличию источника. Проверка «перед публикацией» не должна быть только скрывающей CSS-галочкой.

Если выбран экспорт, держи публичный ZIP исходников отдельно от частной резервной копии. Проверяй восстановление в новой директории; исключай активные сессии и секреты из общего пакета. Не заимствуй приватный релиз исходного автора как шаблон нового проекта.

## Проверки при создании сайта

Конфигурационный скрипт в этом скилле проверяет структуру входных данных, базовую читаемость палитры и пути. Он не проверяет браузер, доставку сообщений, физические размеры изображений или защиту сервера. Для реализации выбери проверки по возможностям сайта: например, фильтр по двум категориям, скрытая работа по прямой ссылке, сохранение правки после перезапуска и форма при недоступном сервисе. Тесты формы используют заглушку доставки.
